Goal

A quiet, professional operator console. Chat is the hero; everything else (sessions, tasks, MCP, channels) follows one list pattern, one dialog pattern, one empty-state pattern. Dark-first, light-intact, keyboard-usable, no layout jank on stream.

Current state (verified)

  • Monochrome oklch tokens, primary ≈ near-black/white, tiny radii.
  • Sidebar: 13 flat items, fixed w-56, no grouping / collapse / mobile drawer.
  • Chat header + app header both show context; title rename is double-click-only.
  • Bubbles at max-w-[80%], actions hidden below bubble, no timestamps.
  • Composer always enabled (disabled=false), no stop button, hint line is 11px.

Desired behavior

  • Grouped nav, collapsible sidebar, real mobile drawer, calmer header.
  • Readable transcript column (max-w-3xl centered), hover toolbar, streaming caret + stop.
  • Composer hierarchy: input first, attachments/chips visible, slash palette polished.
  • One list row pattern everywhere; hover-reveal replaced by always-visible overflow menu.

Risks + mitigations

  • Streaming layout shift - reserve caret space, content-visibility, rAF-coalesced rail (already in ChatView).
  • Light-theme regressions - QA both themes per view; fix destructive-fg first.
  • Touch loss from hover patterns - always-visible overflow on coarse pointers via media query.
  • Scope creep into features - this plan is styles + structure only; no API changes.

Build order (C approved - expressive, chat/sessions/tasks first)

  • Tokens + focus + radii (UX-01, UX-12 partial)
  • Shell: sidebar groups + header popover (UX-02, UX-03)
  • Chat column + toolbar + composer stop (UX-04/05/06)
  • List pattern + skeletons + dialogs (UX-08, UX-09)
  • Canvas/rail onboarding + feedback rules (UX-07/10/11)

Verify each step with pnpm --dir webui test + manual dark/light + 360px pass.
