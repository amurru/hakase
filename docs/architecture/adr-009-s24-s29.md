# ADR-009: Flow Guard S24-S29 Hardening Lane - Approve with Conditions (7 conditions)

Status: Approved with conditions. The S24-S29 close-out
(`docs/flow-guard/s24-s29-blueprint.md`, `s24-s29-inventory.md`) is
approved for implementation on branch `develop` subject to the 7 binding
conditions below. Each condition names the exact code it constrains; a
slice is not done until its condition's acceptance test is green.

Context: after S01-S23 the remaining hardening is file-creation races
(S24), grant-leg binding (S25), output markup (S26), pip supply chain
(S27), write-path deny-first and skills confinement (S28), and the lane
scan (S29). No new tools, no policy-schema change, no label-version
bump. Grounded anchors: `internal/sandbox/scopedfile.go` (new S24
choke), `internal/sandbox/fileops.go:156-257` (write_file/patch),
`internal/agent/agent.go` save_skill/download/checkpoint + `:2182`
instruction, `internal/permissions/flow_grant_v2.go` +
`internal/agent/flow_grant_v2.go` (S25 twins), `internal/agent/pip_pin.go`
+ `exec_choke.go:runPipInstallViaChokeArgs` (S27).

## Condition 1 - Scoped writes only (S24)

Tool-path writes go through `ScopedWriteFile*`/`ScopedCreateFile`
(confine + MkdirAll + EvalSymlinks re-check + Lstat refusal + O_NOFOLLOW
open, O_EXCL create-only). Remaining raw sites carry `// s24-allow:`
with a fixed-path/lock/append/rename justification; test-only IO in
`_test.go` is excluded. Tests: `TestS24ScopedExclusiveCreate`,
`TestS24NoFollowSymlink`, `TestS24OverwriteNeedsFlag`,
`TestS24EscapeDenied`, `TestS24ParentSymlinkEscapeDenied`,
`TestS29ScanInventory`.

## Condition 2 - Joint binding, dual-accept, fresh approval (S25)

The four grant legs bind one joint hash (`JointGrantHash`); every fresh
approval mints twin v1+v2 records; consumption is dual (`ConsumeFlowGrantDual`):
StartLabel accepts either (pre-upgrade grants keep working), narrowed
labels require v2 (fresh), one dispatch drains both twins (one-shot
across stores). Pre-dispatch, python-gate, sandbox file/shell gates and
the resume flow branch all use the dual paths. Tests:
`TestS25JointHashBindsAllLegs`, `TestS25DualAcceptStartLabel`,
`TestS25NarrowedRequiresFreshV2`, `TestS25AgentDualRecords`, plus the
updated `flow_h1`/`flow_loop4` approve-then-run tests minting twins.

## Condition 3 - Both tag families neutralized, no span over 32 (S26)

Model/human-visible flow text neutralizes open and close angle-tag
spans; spans over 32 runes withhold with a length-only marker; order is
redact-then-neutralize-then-truncate; audit carries hashes only.
Tests: `TestS26BothTagsNeutralized`, `TestS26LongTagWithheld`,
`TestS26Boundary32Allowed`, `TestS26DenialNeutralized`.

## Condition 4 - Exact pins, require-hashes, transitive, .venv integrity (S27)

Strict mode (`PipStrictPins`, additive, default off) requires exact
`==` pins on allowlist entries, recorded hashes when `PipHashes` is
configured (`--require-hashes` argv), refuses extras/ranges/URLs and
the installer itself, and verifies .venv (`pyvenv.cfg` + hook trust)
before the choke. Non-strict keeps exact S18 behavior and S22 argv.
Tests: the six `TestS27*` names in the inventory index.

## Condition 5 - Deny-first + skills confinement, :2182 closed (S28)

`denySkillsWrite` refuses Python-library writes before MkdirAll (deny
wins); policy deny still evaluated first at taskResolve; the
orchestrator instruction never routes around a write_file denial via
system_exec (deny-first, stop-and-ask wording pinned as a const).
Tests: `TestS28DenyFirstOrdering`, `TestS28WriteFileSkillsConfined`,
`TestS28PatchSkillsConfined`, `TestS28NonSkillsWriteAllowed`,
`TestS28NoBypassInstruction`.

## Condition 6 - Scan + inventory land last (S29)

`TestS29ScanInventory` fails the lane on any raw write outside the S24
choke (or without `// s24-allow:`) and any label literal outside the
sanctioned sites (Meet-only); `TestS29ChokeInventory` round-trips every
slice's entry point; `TestS28*`/`TestS24*` stay green underneath.
Allowlist growth requires an ADR note.

## Condition 7 - Lane-wide invariants (all slices)

Meet-only label combination; FlowEnabled passthrough (no flow paths run
without a v2 policy); unknown-sink fail-closed on narrowed labels; no
v1 behavior break except through the V1-DELTA register (production
registers nothing; `TestV1DeltaRegisterUnregisteredInert` pins
byte-identical v1); hash-only audit/logs; TTL/cap discipline unchanged
(15m, 1024, evict-oldest fails closed to re-ask).
