Date: 2026-09-12 (r1). Revision r2 2026-09-12: incorporates security audit findings C1-C3 + H1-H6 as normative requirements (fail-closed gates, redaction, adopt atomicity, replay least-privilege). ## 1. Core idea (mental model)

Current hakase evolver is single-sample SGD with one gradient step and a weak gate, on code only:

- Organism = `skills/<name>.py`, evaluator = hand-written `skills/<name>.eval.json` (`contains/exact/regex`, `train:true` vs `train:false`), mutator = one LLM call returning a whole-file ` ```python ` fence, selection = `candidate_train - incumbent_train >= 5%` AND no holdout regression, `.bak` rollback, `<30%` auto-deprecate. Driver = `hakase skill evolve [--mutate]` or cron `native:"evolve"`.

SkillOpt treats the markdown skill document itself as trainable weights (a compact `best_skill.md`, 300-2000 tokens, zero extra inference calls at deploy time) and trains it with optimizer discipline: mini-batch rollout, reflection into bounded `add/delete/replace` edits, LLM-ranked edit budget (learning rate + scheduler), validation-gated acceptance on a disjoint slice, epoch-boundary slow update (momentum) + optimizer-side meta memory, rejected-edit buffer as negative feedback, staged proposals pinned to a live-file hash with explicit human adopt.

We only want the second SkillOpt workflow: **SkillOpt-Sleep** (`skillopt_sleep/`: harvest -> mine -> replay -> consolidate behind held-out gate -> stage -> adopt). The research trainer (`skillopt/`, YAML configs, WebUI, six benchmarks) is for papers, not for this TUI agent. Sleep maps 1:1 onto hakase cron + `sessions/*.json` + markdown skills, and every idea below is a Go port, not a Python dependency.

The highest-value gap: the most valuable skills (`SKILL.md` under `.agents/skills/`) are unevolvable by design today. All new work targets them. Python utils (small deterministic functions, free `.venv` evals) keep the existing single-mutation loop.

## 3. SkillOpt wisdom incorporated (ported, not depended on)

Reference files (design specs to reimplement in Go, not to import): `skillopt/optimizer/{skill,clip,slow_update,meta_skill,skill_aware}.py`, `skillopt_sleep/{consolidate,cycle,gate,memory,types}.py`. Key mechanisms and our ports:

- Bounded `add/delete/replace/insert_after` edits with `{content, anchor/target, rationale}`; `rank_and_select` top-L by optimizer LLM (learning_rate = max edits, default 4; scheduler `constant|linear|cosine`); fallback truncation. Port: `internal/skill/sleep_types.go` + applier.
- Validation gate: `select_gate_score(hard, soft, metric, w)` with `hard|soft|mixed`, strict `candidate > baseline` accept, `gate_no_regression` per-task no-regress option, `holdout_leaked` detection (val not disjoint from train -> `reject_unverified`, stage-but-never-certify), fresh final replay verdict with tentative-applied rollback. Port: pure Go gate functions.
- Train/val/test split with `origin: real|dream`; dream quarantined to train, test write-only for the caller. Port: miner split with seed 42.
- Protected regions: `SLOW_UPDATE`/`APPENDIX`/`LEARNED` marker blocks step edits can never touch; appends insert before earliest marker; markers stripped from edit content. Hand-written `SKILL.md` top half untouched, learned block at tail. Frontmatter frozen.
- Skill-aware reflection (default off): `SKILL_DEFECT` (gated body edit) vs `EXECUTION_LAPSE` (ungated protected appendix reminder); incompatible with full-rewrite modes (we stay `patch`-only).
- Slow update (momentum) + meta skill (optimizer-side memory, never deployed): epoch-boundary longitudinal compare (`improved|regressed|persistent_fail|stable_success`) driving a guidance block / optimizer memory file.
- Staging over promotion: timestamped dir with `report.md/json`, `diagnostics.json`, `evidence.jsonl` (redacted, truncated, flaggable off), proposals pinned to `live_sha256+realpath`; explicit `adopt --skill|--all-skills|--legacy`; `auto_adopt` never for fan-out; per-skill fan-out behind flag with per-group baselines and gate rows.
- Observability: every 0.0->0.0 night self-diagnoses via `holdout_detail[{id, hard, soft, response_len, response_head, why}]` + `reflect_raw[:1200]` + `call_error` (empty response = backend failed; non-empty-but-failing = judge strict or edit useless).
- Honest scope: gains hold where tasks recur with checkable signal; elsewhere flat within noise (single-seed +-1-2pts is not a win); gate keeps worst case bounded. `evalkit` paired A/B (McNemar + bootstrap CI) required for any "B beats A" claim.
