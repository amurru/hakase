# Spec: ADK Adoption — use more of `google.golang.org/adk/v2` (v2.6.0)

Governing issue: #86 (Tier-3, supports all P0). Base: `go.mod:37` (`adk/v2 v2.6.0`, `genai v1.71.0`).

**Scope:** replace bespoke runners with ADK primitives where they already exist. Non-goals: cloud backends by default, `adk web` Dev UI, eval harness port (none in Go module).

## Decisions

- **Adopt where ADK is strictly more maintained.** Delegation runner, workflow orchestration, artifacts, plugins, skill toolset, A2A all exist in-module and are unused (grep `agenttool|workflowagents|skilltoolset|remoteagent|PluginConfig|load_memory` in `internal/` = 0 hits, only generic `artifact` words in comments). Cloud backends (`session/database`, `session/vertexai`, `memory/vertexai`, `artifact/gcsartifact`, `telemetry`) stay opt-in only, fail-closed like `DurableADKService` (`internal/session/adk_service.go`).
- **Keep what is genuinely better local.** Custom session JSON + snapshots/rewind, memory notes + hybrid KB retrieval, hooks runner trust model, own compaction cascade, own skill eval + sleep `evalkit` stay (no `bench.json` in repo; "bench" hits are Go `Benchmark` tests + `internal/skill/eval.go`). ADK `session/compaction` (`LLMSummarizer`) and `memory.Service` do not cover pins/hybrid/skill-awareness.

## Security considerations (post-Flow-Guard review, 2026-10-28)

The validation pass below is dated 2026-10-08 and predates Flow Guard (#124, merged 2026-10-25): per-session (trust x audience) labels with monotone narrowing, permissions.json v2 pre-dispatch `LookupWithLabel` + post-admission withhold/redact, the `flow_blocked` audit family, and the post-release hardening commits (redaction floor 16->10, Windows case-insensitive matching, SameFile dir identity, download rooting, H3 re-redacted truncated previews). Every AD below now carries explicit security constraints; the cross-cutting ones are:

- **Label contract is the invariant.** Any newly adopted ADK path must resolve the session label the way the existing gates do (`flowLabelForCtx` precedence: delegate state -> session snapshot -> registry -> start label) and must narrow, never widen, the parent (S11: taint rides results back via `Meet`). Adoption that silently bypasses label resolution is a security regression, not a refactor.
- **Trust tiers for injected content.** Tool output is DATA (UNTRUSTED_DATA wrapping, `buildSubAgentInstruction`), skill content is semi-trusted instruction material (configured dirs + committed library), A2A peer output is DATA from an unauthenticated-by-default peer. Each AD that introduces a new content channel must name its tier and its injection policy before landing.
- **ADK ordering is load-bearing.** In ADK v2.6.0 `base_flow.go`, the plugin manager's callbacks run **before** the agent's own callbacks and short-circuit them on a non-nil response (BeforeModel :967, AfterModel :1113, tool callback sites :1135+). Security callbacks (flow asks, redaction, deny) therefore depend on ordering, not just presence; see AD-004.
- **Session-state copy review (from AD-001 landing).** `agenttool.Run` copies the parent session's ADK state into the child session, minus `_adk`-prefixed keys (`agent_tool.go:165-181`). Effectively empty today because nothing writes session state outside ADK internals, but nothing enforces that: T1.5 pins it (a test asserts the inherited state carries no hakase keys, and a review rule says any future writer of session state must re-check this path).

## Specs

### Spec AD-001: `agenttool.New` replaces bespoke delegation

- Wrap 3 sub-agents once (`tool/agenttool.New(agent, &Config{SkipSummarization})`) instead of per-call `llmagent.New` + `runner.New` + `InMemoryService` (`internal/agent/delegate.go:337-433`). Keep gate wrappers + blocked-tools filter (`FilterBlockedTools :591-600`, consumed by `BuildSubAgentTools :629-658`; blocked list `:29-37`), delegation cache, HITL pause-capture (`resume.go`). Re-verify `transfer_to_agent` isolation semantics (prompt `agent.go:1891`).
- Landing notes (T1.1, ADK v2.6.0): the delegate_task handler stays the parent-facing functiontool (structured result preserved; `SkipSummarization` must stay **off** — with it on, the parent LLM never sees the delegation result and cannot continue planning). The run machinery (runner, per-attempt `InMemoryService`, session create with parent-state copy, artifact forwarding, event consumption) moved to `agenttool.New(...).Run`, invoked through a structural `Run(agent.Context, any)` assertion pinned by a canary test. Loop side effects ride llmagent callbacks: reporter streaming + degeneration guard fed per streamed partial chunk (chunk granularity, as the bespoke loop), files harvested in `BeforeTool`. The watchdog cancels through a `cancelableAgentCtx` wrapper (ADK's Context cannot go through `context.WithCancel` directly). `agenttool` generates the child's ADK session id itself, so gate routing uses an `interfaces.WithDelegationRoute` ctx fallback (`SessionIDFromCtx`/`TaskIDFromCtx`). Repair attempts re-run in a fresh agenttool session and therefore restate the goal with the corrective note; per-call `llmagent.New` remains because tool construction closes over the per-delegation reporter/log routing.

### Spec AD-002: workflow agents for deterministic pipelines

- `sequentialagent.New([plan, execute, verify])` for coding tasks; `parallelagent` for multi-source research fan-out; `loopagent{maxIterations}` + `exitlooptool` for refine loops; sleep night stages (`internal/sleep/cycle.go`) as Sequential instead of hand-chained steps. Package `agent/workflowagents/*`; `workflow` graph only if branching needed.
- Landing notes (T1.3, opt-in `workflow_delegation`): the pilot is a three-stage `sequentialagent` (plan → execute → verify) wrapping `general_purpose` delegations only, off by default, so cost/behavior stay opt-in. Only the execute stage carries tools and the hook/gate callbacks; planner and verifier are tool-free and read the shared session transcript. All three share one `delegateRunState`, so reporting, guard feeding, watchdog pings, and file harvesting behave identically to the single-agent path (pinned by `TestDelegateHandlerWorkflowPilot`). Escalation is textual: the verifier ends with `VERIFIED`/`NOT VERIFIED` and the parent orchestrator decides; the verdict does not by itself change the delegation status. The sleep cycle was rejected as the pilot: its stages are plain functions with spend guards, eval gates and staging, so wrapping them in workflow agents would be adoption for its own sake (recorded in the AD-002 decision).
- Security constraints (2026-10-28): workflow children run in the **same invocation context** (v2.6.0 `sequentialagent/agent.go:79-89` passes the parent ctx straight to `subAgent.Run` — no fresh runner, no fresh session), so registry-based label resolution (`flowLabelForCtx`) carries to child tools unchanged and child narrowings fold into the same session via the existing gate paths — pin this with a flow test, do not assume it. Out-of-runner pipelines (the sleep cycle has no registered hakase session) must seed an **explicit** label via `WithDelegateFlowState` (StartLabel for v1 parity; a dedicated sleep label if/when a sleep policy exists) instead of relying on the unregistered-session fail-closed (nil -> narrowest under v2), which would deny legitimate sleep egress. `loopagent`/`exitlooptool` inherits the same ctx and adds no new channel.

### Spec AD-003: `artifact.Service` for `outputs/`

- `artifact.InMemoryService()` in `runner.Config` (`agent.go:2637`); migrate `outputs/media` + `outputs/cron` reports (present today; no `outputs/sleep` dir yet - evidence lands there when the sleep loop ships) to versioned artifacts; add `loadartifactstool.New()`. Path-compat shim for Telegram `CronEvent` + web UI consumers.
- Landing notes (T2.1): `artifact.InMemoryService()` is wired into the main runner and `load_artifact` is registered on the orchestrator under the new `artifact` flow action (`flowMapTool` maps the artifact name as the resource; a missing name maps to `*` so a malformed call cannot dodge a family rule). Two deliberate deviations from the wording above: (1) **ADK's `loadartifactstool` is not used** — its `ProcessRequest` injects artifact content into the request before any tool callback can gate that content, so the audit/approval path would be bypassed; a small gated `load_artifact` functiontool replaces it (text returned redacted, binary returns mime/size and the model keeps using the path the producing tool reported). (2) **Disk `outputs/` stays primary** — the web UI and Telegram consume real paths and artifacts are in-memory, so media producers save to both; cron/sleep reports remain disk-only (human-review outputs with no reviewing session, never model-read). Wiring artifacts into the flow gate exposed a real gap: the flow layer passes a **bare policy-default ask** through (v1 parity) on the assumption that a per-tool approval path exists; `load_artifact` has none, so the handler refuses a default-ask load itself. Rule-backed asks still route to the human via the pre-dispatch gate and proceed when approved.
- Security constraints (2026-10-28): artifacts are a new data channel the flow model does not label — tool-gated egress (`LookupWithLabel` on shell/file/download paths) does not cover artifact reads. `loadartifactstool` gets a pre-dispatch policy before landing: evaluate under the caller's session label with a v2 rule family (`artifact` action), fail-closed (ask) when no rule matches, and run secret-shaped content through `RedactSecrets` before a result enters context (cron reports are exactly the secret-bearing case; floor 16->10 per ad4f439 applies). Artifact **writes** stay system-initiated (media/cron/sleep producers only); the model never gains a save-artifact tool in this adoption.

### Spec AD-004: `plugin.Plugin` consolidation

- Merge hooks-runner adapters (`agent.go:128-160`), `VisionInjectionCallback`, `ToolResultGuard`, sidekick watcher, audit into ordered plugins via `runner.PluginConfig`. Preserve deny/override order; pin with `hooks_wiring_test.go`, `toolresult_guard_test.go`. API: `plugin.Plugin{Config{Name, Before/AfterModel/Tool/AgentCallbacks}}`.
- Security constraints (2026-10-28): this is the one AD where ordering is security, not hygiene. The flow gates (`CheckPreFlowAsk` / `CheckPostFlow`) live **inside** the hooks-runner adapters being merged, and flow-guard's C1 rule (post-admission: on `runErr != nil`, redact + fold, then return `(nil, redactedErr)` — never a non-nil result override, which would make ADK drop the tool error) must survive the migration. Because plugin callbacks run before agent callbacks and short-circuit on non-nil responses (see Security considerations), a plugin that returns a result can silently bypass a later gate plugin: pin the full chain order (flow ask -> hooks deny -> redaction) in a dedicated ordering test, not just the existing wiring tests. The AD-001 run-state callbacks (delegateRunState) join this consolidation as their own plugin and keep chunk-granularity guard feeding.

### Spec AD-005: `SkillToolset` + A2A (deferrable)

- `skilltoolset.New(Config{Source})` backed by existing skill dirs (`internal/skill/skill_discovery.go:38`); keep `skill://` MCP serve for external hosts; A/B via skill eval. A2A: `server/adka2a` executor + agent card alongside web server (`internal/web/server.go` route), `remoteagent.NewA2A` to consume peers; scope read-only tools first with `server/authn|authz`.
- Security constraints (2026-10-28): skill content is **semi-trusted instruction material** — a different tier than tool output-as-data. `SkillToolset` lands only behind the existing skill discovery + eval, with skill text treated as instructions that cannot grant new tool authority (a skill cannot recommend its way past a gate; the gate still evaluates the dispatch). A2A peer results are **untrusted data from an unauthenticated-by-default peer**: wrap in UNTRUSTED_DATA, apply the tool-output injection policy, and give the peer a label story before any tool-carrying exchange — read-only first (already specced), and a peer result must not widen the local session label (no `Meet` counterpart exists for remote agents; the local session keeps its own label, peer output only feeds content). A2A egress itself is a network path: subject to the same flow ask/deny evaluation as other egress tools when a v2 policy is installed.

## Non-goals

- `server/adkrest`, `launcher` Dev UI (own chi + Vue SPA stays), `memory/vertexai` default (local store stays), eval port (keep skill eval + sleep `evalkit`).

## Definition of done

- [ ] Delegation via `agenttool` with identical gates/cache/HITL behavior.
- [ ] One deterministic pipeline (sleep cycle or plan-execute-verify) on workflow agents, with the label contract pinned (T1.4).
- [ ] Artifact reads gated under the caller's session label (T2.1 security constraints).
- [ ] Plugin chain order covers the flow gates and the C1 redaction rule (T2.2/T2.3).
- [ ] Suite green + `-race` on touched packages.
