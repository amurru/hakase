## Coverage gaps and missing cases

These are the 9 items named in the tasking as non-blocker follow-ups. None fails the suite, but each is an untested path, imprecise wording, or platform-tolerance that a future test or edit should close.

1. **Medium perf recompute** - `RecomputeFlow` backfill path is described in spec as "recompute by folding stored `tool_result` history, or default `suspicious/internal` when history unavailable." Current `RecomputeFlow` unconditionally defaults conservative without folding history (see `internal/session/flow.go:89-100`). No test drives a pre-v2 file WITH `tool_result` history through a fold. **Gap:** history-fold vs default-conservative branch untested; perf cost of folding large history unmeasured. Suggested case: `TestRecomputeFlowFoldsHistory` (seed N `tool_result` messages, assert folded label != pure default) + a bench with 10k messages. Currently **untestable as specified** (spec allows either branch via "or").
2. **Low prose false-positive** - lowering the all-lowercase floor 16->10 means `Bearer information` (11 lowers) now redacts. Test deliberately switched prose fixture to `use bearer info wisely` (4 chars) and documents the tradeoff in-test. No test pins the `information` case either way. **Accepted tradeoff, but gap:** add an explicit `TestRedactSecrets_LowercaseFloorTradeoff` asserting `Bearer information` DOES redact (fail-closed) so a future floor change cannot silently flip it.
3. **Unlink spelling (negative branch)** - `saveDownloadBody` mismatch branch (`clean != opened => skip Remove`) has no test. `TestS19DownloadSizeCap` only exercises `clean==opened` (unlink happens) and at-cap (no unlink). **Gap:** missing `TestS19DownloadSizeCapMismatchSpelling` (pass `filePath` with `./`, double-slash, or different name sharing `dst`; assert no deletion + error still returned). Falsifiable, currently uncovered.
4. **Windows tolerance** - `matchCandidates` volume-strip + `(?i)` compile, `PathResources` `EqualFold`/`SameFile` collapse, `sameFileOrFold`/`sameDirIdentity` Windows legs are all `runtime.GOOS=="windows"`-gated and **cannot execute on linux CI**. Linux tests assert the POSIX legs (dual-leg kept, `Skip` on windows) and tolerate a volume-variant pair, but the Windows collapse itself is never executed. **Gap:** needs Windows CI or a `GOOS=windows` cross-compile + injected `VolumeName` unit test of `matchCandidates` pure logic (refactor to injectable `goos` param for testability).
5. **`flow.go:324` doc** - lock-ordering comment (`flowBindings` + `flowGrantStore` never held together, evaluator records nothing) is **doc-only, untestable as written**: no test can fail if the doc rots. Options: (a) accept as documentation, or (b) add a `go vet`-style static check (grep that `RecordFlowBinding`/`GrantFlowBinding` never appear inside `EvaluateWithLabel` call graph). Do not guess at a runtime deadlock test.
6. **Spec `truncated_count` wording** - spec says "`truncated_count` is the pre-truncation string count." Code sets `truncated_count = len(pre)` where `pre` is ALREADY the capped subset from `marshalResultStringsCapped` (max 512 strings / 1MB). So the emitted count is the capped-snapshot length (512 on over-budget), not the true pre-walk total (600+ in test). Test only asserts preview length 1..5, never `truncated_count` value. **Gap/wording:** either spec should say "snapshot length (capped at 512)" or code should thread the true total. Suggested: `assertPreviewRedacted` also asserts `truncated_count==len(bulk)-?` once semantics are chosen. Currently ambiguous, so **untestable as written** until wording is fixed.
7. **`flow_blocked` vs admitted naming** - source over-budget leg calls `AuditFlowBlock` (decision `flow_blocked`) then returns `flowBudgetAdmit` (`truncated:true`, admitted). Spec blesses this ("Both legs audit ... + `flow_blocked`"), but the decision name says "blocked" for an admitted result. Only the egress leg's `flow_blocked` is asserted (`TestWalkOverBudgetFailClosed`); the source leg's `flow_blocked`-on-admit is never asserted. **Gap:** add source-leg audit assertion (admit still emits `flow_blocked` + `flow_sanitized`) or rename to `flow_admitted_truncated`. Either way the current test suite does not pin the source-leg audit.
8. **Install-before-load ordering** - all H4 tests call `enableFlowForTest` (Setenv + Install) BEFORE `RecomputeFlow`/`RegisterLoadedWith`. Production `SessionStore.Load -> RegisterLoaded` reads `FlowEnabled()` at load time; if the policy is installed AFTER load (late startup, test that loads first), recompute is skipped and no test covers that ordering. **Gap:** missing `TestRegisterLoadedBeforePolicyInstall` (load with nil policy, then install, assert no retroactive narrowing + no audit). Order-dependent, currently uncovered.
9. **`flowgate.go:1382` nil deref (pre-existing)** - in the `tainted` over-budget block, the egress/source diverge uses `rule` from the preceding requires re-validation (`eff, rule, detail, ok := LookupWithLabel(...)`). When `ok==false`, `rule` is nil yet is passed to `AuditFlowBlock(..., rule, label)`. `flowLabelSnapshot(nil)` handles nil label, and `flowDenialText` handles nil, but `AuditFlowBlock`'s nil-rule handling is not pinned by any test on this path (all over-budget tests use policies where lookup succeeds or is skipped). Pre-existing (not introduced by this diff), no failing test, but **no test proves nil-rule audit is safe here**. Suggested: audit-helper nil-rule unit test + over-budget test with a policy where `LookupWithLabel` returns `ok==false`.
